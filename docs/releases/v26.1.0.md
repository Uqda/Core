# Uqda 26.1

**Uqda is a worldwide encrypted network made only of its users' devices.**
Every device that installs it becomes a node (عُقدة): it gets a permanent
address derived from its own key, connects to the nodes around it, and helps
carry the network's traffic. There is no company in the middle, no account and
no central server. Uqda runs inside the worldwide Yggdrasil network and stays
compatible with it.

26.1 is the release where Uqda becomes easy to set up, safe by default, and
ready to build on.

> **Experimental project.** Uqda is tested extensively but has not had an
> independent security audit. Do not rely on it where a failure would put
> people or critical systems at risk.

## Start in three commands

```sh
sudo uqda setup country=germany   # identity, private network, firewall, fast peers kept healthy
sudo systemctl restart uqda       # setup prints the right command for your system
sudo uqda invite                  # on each new device: sudo uqda join <invite>
```

New to Uqda? Read [how it works](https://github.com/Uqda/Core/blob/main/docs/how-it-works.md)
and [getting started](https://github.com/Uqda/Core/blob/main/docs/getting-started.md).

## New in 26.1

### Easy to join

- **`uqda setup`**: one command creates the node identity, a private network
  with a random 192-bit group password, the inbound firewall, and the fastest
  healthy public peers in the chosen country. On an existing node it keeps the
  identity and only adds what is missing.
- **Invites**: `uqda invite` shows a one-time, expiring invite as text and as a
  QR code; `uqda join` adds the new device. The invite holds no password. The
  new device checks the inviting node over TLS 1.3 against its key, proves it
  has the invite's random secret, and only then receives the group password and
  peers.
- **Automatic peers**: Uqda keeps the wanted number of healthy public peers by
  itself. It replaces a peer that stays down for five minutes and moves to a
  much faster one when it appears. Peers you configured are never touched.

### Safe by default

- **Inbound firewall**, on for new nodes: unsolicited traffic is dropped unless
  a rule allows it by device key, address, protocol and port. Existing nodes
  keep their behaviour, and `uqda status` explains how to turn it on.
- **Replay-proof handshake**: Uqda nodes prove they hold their key on every new
  connection, so a recorded handshake can no longer impersonate a node.
  `RequireFreshHandshake` enforces it in all-Uqda networks.
- **Flood limits**: at most 256 pending handshakes per node and 8 per source.
  The admin API is limited to 64 connections, 1 MiB requests and five idle
  minutes.

### Ready to build on

- [Build on Uqda](https://github.com/Uqda/Core/blob/main/docs/build-on-uqda.md):
  host a website from any node, use a node's authenticated address as its
  identity, write tools against the admin API, and embed a node in an app.
- New commands: `uqda firewall`, `uqda autopeers`, `uqda invite`, `uqda join`,
  `uqda setup`.

### Fixed

- `setup` and `join` keep the configuration file's owner and group, so the
  service can still read it.
- The Debian package installs in containers and chroots without a running
  systemd, and the packaged `root:uqda 0640` configuration no longer triggers a
  permission warning.
- Windows: a rate-limited invite now gets a clear reply instead of a reset
  connection.

### Under the hood

- Requires Go 1.26 or newer to build. Dependencies are updated, including
  quic-go 0.63 and golang.org/x/crypto 0.58.
- The documentation is rewritten in English and Arabic: how the network works,
  networks, getting started, firewall, invites, public peers and building on
  Uqda.

## Install or update

| System | Install | Update |
|---|---|---|
| Linux (systemd, x86-64 and arm64) | `curl -fsSLo uqda-install.sh https://raw.githubusercontent.com/Uqda/Core/main/contrib/install/linux.sh && sudo sh uqda-install.sh install` | `sudo sh uqda-install.sh update` |
| Debian and Ubuntu | `sudo apt install ./uqda-26.1.0-ARCH.deb` | install the newer `.deb` |
| macOS (Intel and Apple Silicon) | `brew install --cask Uqda/tap/uqda`, or the `.pkg` below | `brew upgrade --cask Uqda/tap/uqda` |
| Windows (x64, x86, ARM64) | the `.msi` for your system below | install the newer `.msi` |
| Docker | `uqda-26.1.0-oci.tar` below | |
| Android and Apple apps | SDKs: `.aar` and `.xcframework` below | |

Updates keep your node identity and configuration. Verify downloads against
`SHA256SUMS`. After updating an existing node, run `sudo uqda setup` to add
anything that is missing, such as the firewall or automatic peers.

## Compatibility

- Peering, routing and sessions with Yggdrasil and earlier Uqda releases are
  unchanged. This is checked against the official Yggdrasil implementation:
  peering in both directions over TCP and TLS, packet delivery, reconnects and
  multi-hop paths.
- The handshake extension is optional and ignored by nodes that do not know it.
- Private groups created before 26.0.2 still need the coordinated upgrade
  described in the 26.0.2 notes.

## Known limits

- Some paths go through other nodes rather than directly through NAT, so they
  can be slower than services that punch holes through NAT.
- Uqda hides content, not who is talking to whom. It is not an anonymity network.
- The Android and Apple files are SDKs for app developers, not ready-made apps.
- Installers are not code-signed yet. Verify them against `SHA256SUMS`.
- On Umbrel the app stays on its tested 26.0.5 package for now.
